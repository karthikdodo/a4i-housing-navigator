Checkpoints

The whole run is 4.5 hours. The deploy at T+2:30 is the one that cannot slip.

  1. T+0:00 to 0:20, everyone: agree on the scenario sentence and the brief JSON; create branches; add collaborators to the repo.
  2. T+0:20 to 1:30, in parallel: Prachi embeds the data and tests the decoy filter; Karthik builds the agent on stub tools; Selvan builds the UI on mock JSON; Sid sets up the connection and deploy pipeline; April drafts the deck outline.
  3. T+1:30: the agent swaps its stub tools for Prachi's real SQL.
  4. T+2:30: first deploy to Cloud Run, even if rough; the UI switches to the live URL.
  5. T+2:30 to 3:30: run the decoy demo, add equity audit numbers, fix bugs.
  6. T+3:30: feature freeze; record the video on the live app.
  7. T+4:00 to 4:30: submit the repo, the Skills project link, the deck and the video.

Rules and open decisions

  • One shared GCP project: never rename or drop a table in a4i_housing without saying so in chat.
  • Keep the audit_* columns out of search, scoring and prompts; use them only in the equity audit.
  • Add up the 4 quarters of eviction filings per tract before joining, or every count is 4x too high.
  • Say it plainly in the app and deck: 311 records prove block conditions, not the tenant's unit; eviction filings are modeled.
  • April may cut scope at T+2:30 if there is no deploy.
